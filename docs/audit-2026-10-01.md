# Adversarial audit — defects found and fixed (2026-10-01)

Skeptical read-only review of `demo/`, `frame/`, `web/`, `scripts/`, then
reproduction of every claim by execution. Each row below was observed failing
before the fix and observed passing after. Verified: 42/42 frame, 41/41 demo,
`verify.py` clean, live HTTP smoke green.

## Medium — correctness and drift

- `payout_minor` shadowed the ledger's own computation (`int(round(stake*float(m)))` instead of `gross_return`) — no divergence today, but two sources of truth. The round now records `unit` (the actual draw) for audit.
- Money arrived from the browser as a float-parsed int and ran through `to_cents`, turning `10000` into R$10.000,00. Now `_minor()` asserts centavos with a ceiling.
- `player_id` came from the free-text name: "Ana Souza" and "ana souza" collided, `<script>` survived. Now `slug("wallet", cpf)` — one wallet per person.
- `refresh()` wrote its error into the spin message, so a failed balance fetch overwrote a win with an HTTP error. Split into `refreshError`.
- No request timeouts: a hung POST left the spin button disabled forever. `api()` now aborts at 8s with a readable message.
- Overlapping refreshes could resolve out of order and show a stale balance. Sequence token added.
- Vendor seam accepted `http://` base URLs (aggregator key in cleartext) and would replay the `Authorization` header across a redirect. https-only, cross-host redirect refused, credit reserved before the network call.
- `risk.py` sorted timestamps as strings (`…Z` vs `…+00:00` sort wrongly) and flagged at exactly the limit. Both fixed.
- `verify.py`: markdown links resolved against the repo root instead of the document; the TODO gate covered only `frame/` and self-flagged; `py_compile` wrote `.pyc` files on every run.
- `Limits.breached` used `>` while the wallet correctly used `>`, so a deposit landing exactly on the cap was refused — off-by-one against the player's expectation.
- Modals: no Escape, no backdrop dismiss, no scroll-lock, no dialog semantics; the cashier could stack over the account sheet. Added, plus `web/app/error.jsx` as a render-error boundary.

## Confirmed sound (checked, no action)

RTP math matches the declared tier distribution across 200k simulated spins;
`check_odds`/`gross_return` hold the 1.01 floor and round half-up; React has
zero `innerHTML`; the deposit allowlist rejects `credit` by name; no secrets in
code (`DEMO_API_KEY` is env-only).

## The lesson worth keeping

Every critical row was invisible to review and obvious to execution: a
concurrency bug needs threads, a traversal bug needs a Windows drive letter, an
idempotency bug needs a retry. The audit's own tripwire tests were also
vacuous in one place (asserting an invariant that the filter above it
guaranteed). **A test that cannot fail is not a test** — the same discipline
that caught the `fixtures=0` TypeError earlier in the session.
